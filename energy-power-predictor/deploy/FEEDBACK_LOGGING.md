# 다음 주 재학습 검토를 위한 로그 (재학습 실행 안 함)

1. 예측 화면에서 입력과 예측의 저장에 동의하고 `이 예측 저장`을 누릅니다. 무단 자동 수집하지 않습니다.
2. `내 기록`에서 같은 가전·대수·기간의 실제 Wh를 입력하고 범위를 확인한 뒤 실측값을 저장합니다. 실제 추가요금도 아는 경우에만 별도 입력합니다. 전체 월 청구액과 가전 사용 1회 추가요금을 비교하지 마세요.
3. 예측 저장은 pending_actual, 실측 저장은 evaluated 이벤트로 같은 prediction_id에 연결됩니다. 입력, 타겟 범위, 예측 Wh/원, 실제 Wh/원, 모델 해시, 배포 버전, 오차를 남깁니다. 가격 실제값이 없으면 가격 평가 필드는 null입니다. 오차 0을 강요하지 않고 에너지 max(5Wh, 실측10%), 요금 max(1원, 실측10%)를 v1 기준으로 명시했습니다. 이 기준 이내 여부는 R²나 전체 정확도와 다릅니다.
4. 이름, 브라우저 접근 키, IP, 인증 헤더, CSV 원본, 알려지지 않은 입력 필드는 평가 로그에서 제외합니다. SQLite records 테이블의 기존 보관 규칙은 유지합니다. 파일은 JSONL로 회전하며 컨테이너마다 파일을 나눕니다.
5. 원본 이벤트는 기존 영구 volume의 history.sqlite3 / feedback_events에 트랜잭션으로 보관합니다. JSONL은 같은 volume의 feedback/*.jsonl에 씁니다(파일당10MB, 백업10개). JSONL 쓰기 실패가 나도 SQLite 원본은 남습니다. 삭제 시 로그에는 삭제 표시가 추가됩니다. 이전 로그는 남지만 재학습 추출에서 제외합니다.
6. 다음 주 `docker exec <활성 컨테이너> python deploy/export-feedback.py`로 최신 정정값만 추출할 수 있습니다. 사용자 보고 라벨은 검토가 필요하여 training_eligible=false로 둡니다. power_time은 산술 계산이며 학습된 모델의 정답으로 섞지 마세요. 가전·방식·예측 기간별로 나누고 사람이 검토한 뒤 학습/시간분할 평가해야 합니다. 실측 없는 기록·삭제된 기록은 추출하지 않습니다.

현재 요청에 따라 서버 저장만 구성합니다. CloudWatch 전송은 EC2 IAM 역할 미연결로 비활성입니다. 다음에 연결할 때 호스트 Docker volume 경로의 feedback/*.jsonl을 Agent의 파일 로그 수집 대상으로 설정하면 됩니다. 같은 event_id는 중복 제거해야 합니다. AWS 자격증명/키를 프로그램에 넣지 않습니다.
